# PROJECT_INDEX — symbol map

`CLAUDE.md` is the operating manual (build chain, which tool owns what, house rules).
**This file is the level below it: where inside a file a thing lives.**
Read a range with `sed -n 'A,Bp' <file>`. Never read these files whole.

Machine copy: `PROJECT_INDEX.json`, regenerated by `python tools/mkindex.py`.

**The deliverable is `native/`; `src/derelict/*.html` is the previz.** The
native index comes first here for that reason.

## native/src — the exe (25,344 lines, 49 files)

49 files, 83 sections, 310 exported symbols. Two headers are generated and
carry no symbols — go to the tool that writes one, not to the header:
`plan_data.h` 6,755 lines ← `tools/nativepack.py`, `story_data.h` 905 ←
`tools/storypack.py`.

Two files are not ports of anything in the previz, because the previz has no
equivalent: `menu.c` (the title card and the wake) and `props.c` (the room
props). Everything else on this list crossed over from `map.html`.

A module's public surface is its filename as a prefix — `lumi*`, `zom*`,
`story*`, `fx*`, `ad*` (doors), `render*`, `game*`. Everything else in a file
is `static` and is found from the section it lives under.

### story.c — the director, section by section

`story.c` is where every scene, trigger and objective lives, and it is the
file the current pass is moving in. Read it by range.


Exports: `storyEvent storyInit storyStep storyFrame storyHUD storyDrawWorld
storyDrawGuns storyInteract storyScene storyProbe storyClearRoutes storyOver
storyFail storyDamaged storyLockLook storyLockMove storyCamY storyCamRoll
storySpeedScale storyAutoTarget storyAutoInteract storySetTrace storyFreeCam`

Three things in `story.c` are not scenes and are worth naming: `settleItem`
puts every pickup on a deck a player can walk to (`deckNear` + a route
test), `snapQuests` does the same for the thirteen objectives and writes
`QT[]` — which every reader of a quest target uses instead of the packed
`SQ_TARGET` — and `storyClearRoutes` walks each of those routes with the
furniture in and deletes whatever is standing on one.

`QUESTS` is a six-column table: event, banner text, the plan point the compass
needle holds, the event that standing on that point fires, and the English
banner. The arrival event is the backstop for `the-deck-plan-is-not-the-ship`
— and the point itself is only a suggestion: `snapQuests` in `story.c` solves
each one against the nav lattice at boot and writes `QT[]`, which is what
every reader actually uses.

## story/ — the design, as data

`tools/storypack.py` compiles these into `native/src/story_data.h`. What stays
as code in `story.c` is the part that is genuinely logic.

```
dialogue.json   51 lines of Korean.  trigger "chain" = play when the line above ends
scenes.json     S0..S12, the flags each one sets
spawns.json     14 encounters, their waves, methods (CRACK / VENT / COCOON) and on_clear
```

Beside them, the two hand-written design inputs the port answers to:
`LUMI_FPS_구현명세서_v1.md` (44 KB, the spec sections `story.c` cites by number)
and `AI_작업카드.md` (the session cards; `-scene N` and `-probe` are card 0's
`goto`/`mark` console, delivered as flags).
