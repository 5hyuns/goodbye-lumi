## 1. 게임 개요

- **시점:** 1인칭. 주인공은 끝까지 무언(음성·자막 없음). 모든 대사는 루미의 것.
- **핵심 루프:** 루미를 따라간다 → 적을 처치한다 → 에너지팩을 회수한다 → 갤러리로 돌아와 장착한다 → 함선이 더 기운다.
- **승리 조건:** 에너지팩 3개 회수 + 최종 방어전 90초 생존 + 캡슐 탑승.
- **패배 조건:** 플레이어 체력 0. 또는 최종 카운트다운 0초에 캡슐 미탑승.
- **음성:** 없음. 루미 대사는 **자막 UI + 비프음**으로만 처리(높낮이·속도로 감정 대체).

## 3. 루미 (LUMI) 사양

### 3.1 외형·물리
- 직경 0.35 m 구형, 지면에서 **1.4 m** 높이에 부유. 미세한 상하 진동(±3 cm, 0.8 Hz).
- 최대 이동 속도 **8.0 m/s** (플레이어 달리기 6.6보다 빨라야 추격 구간에서 문 개방이 막히지 않는다). 벽·적과 충돌하지 않음(고스트 콜라이더).
- 전면 원형 디스플레이(직경 0.22 m) + 전방 스포트라이트(각도 55°, 사거리 18 m, 색 5600K).
- 몸체 하단 상태 LED 링: 청백(정상) / 황(경고) / 적(비상 모드 이후).

### 3.2 위치 모드 (상태 머신)

| 모드 | 위치 | 발동 |
|---|---|---|
| `LEAD` | 플레이어 전방 3.5 m, 진행 방향 조명 | 이동 중 기본 |
| `HUD` | 플레이어 시야 기준 **좌하단**, 카메라에서 0.55 m, 화면 좌하 25% 지점에 고정 | 전투 중 / 정지 중 / 기본 체력 표시 |
| `PANEL` | 문·콘솔 패널 앞 | 문 개방, 단말 조회 |
| `DOCKED` | 갤러리 도킹 포트 (196,556)에 고정 | S9 이후. 이동 불가 |
| `OFF` | 소멸 | S10 도킹 직후 (조명·디스플레이 전부 소등) |

`LEAD` ↔ `HUD` 전환은 1.0초 보간. 전투 시작(적 인지) 시 자동으로 `HUD`.

### 3.3 디스플레이 상태

| 상태 | 표시 내용 | 사용처 |
|---|---|---|
| `EYES_IDLE` | 기본 눈(둥근 점 2개, 3~6초마다 깜빡) | 대기 |
| `HEARTBEAT` | 심박 파형 애니메이션 | **오프닝 최초 발견**, 스캔 시 |
| `VITALS` | `체력 ██████░░ 74%` + `♥ 96` (BPM) | **기본 HUD 상태** |
| `EYES_TALK` | 눈 + 대사 싱크로 눈꺼풀/동공 움직임 | 대사 재생 중 |
| `SCAN` | 회전 링 + 격자 | 스캔·조회 |
| `OPEN` | 텍스트 `OPEN` + 진행 게이지 | 문 개방 |
| `COUNT` | 큰 숫자 (90 → 0) | S10 카운트다운 (콘솔 스피커로 대체) |
| `WARN` | 적색 삼각 + `!` | 체력 30% 미만, 매복 경고 |

**오프닝 전용 시퀀스(요청 사양):** `EYES_IDLE` → (플레이어 인식) → `HEARTBEAT` 2.0초 → `EYES_IDLE` → 첫 대사.

### 3.4 루미의 3대 기능 (전부 실제 게임플레이 기능이며, 잃으면 체감된다)
1. **광원** — 함선의 주 조명이 죽어 있으므로 루미가 사실상 유일한 넓은 광원.
2. **체력 UI** — 아래 4장.
3. **문 개방** — 루미 없이는 전진 불가.

> S10에서 루미가 도킹하면 셋 다 동시에 사라진다. 이 상실이 최종 방어전의 난이도이자 감정 연출이다. 이 규칙을 절대 완화하지 말 것.

### 3.5 담담함 규칙 (연출 금지 사항)
- 루미의 도킹 이동은 **평소와 같은 속도**. 느려지거나 멈칫하는 애니메이션 금지.
- 도킹 순간에는 음악을 넣지 않는다. 슬픈 음악은 **사출 이후에만**.
- 루미는 확인을 구하지 않는다. 플레이어에게 선택지를 주지 않는다.

|---|---|---|

| **피격** | 화면 가장자리 | 적색 비네트 + 방향 지시자 |
| **BPM 규칙** | 루미 디스플레이 | 평시 78~92, 전투 중 120~165, 체력 30% 미만 170+. 심박음 SFX와 동기화 |

**대사 중 UI 전환:** 대사가 재생되면 루미 디스플레이가 `VITALS` → `EYES_TALK`로 바뀌고, 체력 수치는 그 동안 보이지 않는다. 대사 종료 0.5초 후 `VITALS` 복귀. 단 **전투 중에는 대사를 재생하지 않는다**(자막을 읽을 수 없는 타이밍 회피 + 체력 UI가 가려지면 안 되므로).

## 18. AI 구현 절차 (반드시 이 순서로)

스토리를 씬별 스크립트로 짜지 않는다. **시스템 5개를 먼저 만들고, 스토리는 `data/*.json`으로 채운다.** 각 시스템은 별도 세션에서 만들며, 세션별 지시문은 `AI_작업카드.md`에 있다.

| 순서 | 시스템 | 읽는 데이터 | 완료 조건 요약 |
|---|---|---|---|
| 0 | 좌표 매핑 + 디버그 콘솔 | `rooms.json` | SVG→월드 변환 함수. `goto/flag/spawn/say/door` 콘솔 명령 |
| 1 | 플래그 저장소 | — | 12장 변수 전부. 변경 시 이벤트 발행 |
| 2 | 트리거 볼륨 + 이벤트 버스 | `scenes.json` | 영역 진입/아이템/전멸 → 이벤트 ID |
| 3 | 대사·자막 재생기 | `dialogue.json` | 큐잉, 전투 중 보류, 루미 디스플레이 연동 |
| 4 | 루미 상태 머신 | — | 위치 모드 5종 × 디스플레이 8종 |
| 5 | 스폰 디렉터 | `spawns.json` | 웨이브 타이밍, 방식 5종, 동시 20마리 상한 |
| 6 | 문·아이템·팩 | `doors.json`, `items.json` | 루미 3 m 규칙, 슬롯 콘솔 |
| 7~ | 씬 S0~S12 | `scenes.json` | 트리거 볼륨 배치 + 데이터 검증만 |

**규칙**
- 세션당 작업 하나. 코딩 전 수정 파일 목록 제시 → 승인 → 작성 → 콘솔 명령으로 자체 검증 → 커밋.
- 마일스톤마다 `ARCHITECTURE.md` 갱신(시스템 구조, 이벤트 이름, 파일 위치). 다음 세션은 명세서 + ARCHITECTURE.md만 읽고 시작.
- 기존 이동·총기·적 코드는 수정 금지. 필요하면 어댑터를 새로 만들어 붙인다.
- 감(feel) 수치는 첫 구현에서 맞지 않는 것이 정상. 피드백은 숫자로 준다.
