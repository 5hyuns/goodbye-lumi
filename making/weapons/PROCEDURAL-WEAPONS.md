# 절차적 무기 시스템 — 기술 명세

에셋 파일 0개. 메시와 텍스처 전부를 실행 시점에 코드로 생성하는 1인칭 무기 시스템.
구현체는 단일 HTML 파일(WebGL2, 약 80KB)이며 GLSL은 네이티브 OpenGL로 그대로 옮겨진다.

- 무기 3종 — 권총(슬라이드), 로터리 캐논(회전 총열), 더블배럴 샷건(브레이크 액션)
- 절차적 지오메트리, 절차적 노멀맵/알베도/러프니스, PBR, 파티클, 포스트 프로세스
- 배경은 셰이더 그리드 하나뿐. 무기 검수를 위한 스튜디오 오빗 뷰 포함

---

## 1. 절차적 모델링

프리미티브를 두 개로 줄였다. 나머지는 전부 이 둘의 조합이다.

### loft(rings, mat, texScale, opts)

같은 점 개수를 가진 링(3D 점 배열) 목록을 순서대로 이어 표면을 만든다.
회전체, 각진 박스, 튜브, 테이퍼 몸통이 전부 이 함수 하나로 나온다.

- `u` = 링 둘레 누적 길이 × texScale, `v` = 링 간 평균 이동거리 누적 × texScale
- `opts.flip` 으로 법선 반전(복도·내부 면), `capStart`/`capEnd` 로 팬 삼각분할 마감
- **링 점 개수가 다르면 즉시 예외를 던진다.** 원통(20각)과 사각(8점)을 이으려다
  `rings[k][i]` 가 undefined 가 되는 사고가 실제로 났다. 개수가 다른 단면을 이을 때는
  `resample(ring, n)` 으로 둘레 길이 기준 재샘플링해서 맞춘다.

### 링 생성기

| 함수 | 용도 |
|---|---|
| `ringCircle(cx,cy,z,r,seg)` | 원 |
| `ringRect(cx,cy,z,sx,sy,c)` | 모서리 깎은 사각형 (8점) |
| `ringTri(cx,cy,z,R,c)` | 모서리 깎은 정삼각형 (6점) |
| `resample(ring,n)` | 닫힌 폴리곤을 n점으로 재샘플링 |

### 파생 함수

- `chamferBox(cx,cy,cz, sx,sy,sz, c, mat, ts)` — 사각 링 4단(축소–본체–본체–축소)을 로프트
- `lathe(cx,cy, profile, seg, mat, ts)` — `profile[i] = [r, z, mat?]`, 세그먼트별 머티리얼 지정 가능

### finalize(builder) — 법선/탄젠트 스무딩

면 법선을 먼저 구하고, **같은 위치의 면끼리 각도 50도 이내일 때만** 평균한다.
이것 하나로 실린더 원주는 매끄럽고 챔퍼 면은 각지게 나온다.
탄젠트도 같은 그룹으로 평균한 뒤 그람-슈미트 직교화하고, 종법선 부호를 w에 담는다.

출력은 정점당 13 float 인터리브: `pos3 / nrm3 / uv2 / tan4 / mat1`.

> **"네모박스처럼 보이지 않게" 하는 것은 폴리곤 수가 아니라 모서리 챔퍼다.**
> 챔퍼 면이 스페큘러 하이라이트를 가느다란 선으로 잡아주는 것이 "가공된 금속"의
> 정체다. 챔퍼를 0으로 두면 같은 메시가 즉시 프로그래머 아트로 보인다.

### 삼각 클램프 — 유도되는 치수

로터리 캐논의 총열 클램프는 상수가 아니라 총열 배치에서 유도한다.
정점이 총열을 향하는 삼각형에서 두 조건의 큰 쪽을 취한다.

```
① 인접 변까지        0.5*(RI - OFF)      >= 총열최대반경 + 여유
② 모서리 챔퍼 현까지  RI - 0.866*CI       >= OFF + 총열최대반경 + 여유
```

베벨(CI)을 키우면 ②가 지배한다. 총열 굵기나 배치를 바꿔도 클램프가 자동으로 따라온다.

## 2. 절차적 텍스처

512×512 세 세트를 실행 시점에 GPU에서 생성한다. 실행파일 용량 기여는 0.

### 생성 방식

하이트 함수를 GLSL로 정의하고, 같은 픽셀에서 `H(uv)`, `H(uv+dx)`, `H(uv+dy)` 를
평가해 **중앙차분으로 노멀을 뽑는다.** 하이트 텍스처를 만들고 2패스로 변환하는 것보다
코드가 짧고 밉맵 없는 원본 해상도의 기울기를 쓴다.

MRT로 한 패스에 3장을 동시에 출력한다.

| 출력 | 내용 |
|---|---|
| `oAlb` | 알베도 RGB |
| `oNrm` | 탄젠트 공간 노멀 (×0.5+0.5) |
| `oRMA` | R=러프니스, G=메탈, B=AO, A=하이트 |

AO는 넓은 반경(4텍셀) 하이트 평균과의 차이로 캐비티를 근사한다.
A채널의 하이트는 메인 셰이더에서 마모·도장 벗겨짐에 재사용한다.

### 세 가지 하이트 함수

| 세트 | 함수 | 특징 | 쓰는 곳 |
|---|---|---|---|
| A | `hPlate` | 셀 해시로 플레이트 배치, 볼트, 벤트 슬롯, 서브 그리블 | 판금 전반 |
| B | `hMach` | 원주 방향 홈, 널링 밴드 | 총열, 탄피 |
| C | `hHard` | 넓은 베벨 플레이트, 깊은 루버 슬롯 5개, 지름 8mm 일자 나사 2개 | 권총 하드서페이스 |

C가 A와 다른 점은 **요소가 크고 수가 적다는 것**이다. 손으로 깎은 기계 부품처럼
읽히려면 잔 디테일을 늘리는 게 아니라 줄여야 한다.

### 조정 가능 파라미터 (UI 슬라이더)


색은 sRGB 16진수로 받아 `pow(c, 2.2)` 로 선형 변환해 넘긴다.
이 변환을 빼먹으면 피커에서 고른 색보다 훨씬 밝게 나온다.

### 텍스처 스케일

`TSG = 3.2` (총기 일반), `TSB = 7.2` (몸통 — UV 반복을 늘려 디테일을 잘게).
총열에 TSB를 쓰면 가공 홈이 148개가 되어 모아레가 생긴다.

## 4. 셰이딩

- Cook-Torrance: GGX D, Smith 높이상관 가시성, Schlick F
- 환경광은 큐브맵 없이 **절차적 함수** `envCol(R, rough)` — 밝은 스튜디오와 어두운 실내 두 모드.
  메탈릭 표면이 새까맣게 죽지 않게 하는 데 이것이 전부다.
- 환경 스페큘러는 Karis 모바일 근사 `envBRDF(F0, rough, NoV)`
- 포스트: 16탭 나선 블룸, 색수차, 탈채도, 암부 청록 / 명부 앰버 그레이딩, ACES, 비네트, 그레인

### 가열 발광 — 톤매핑 포화 주의

총열(mat 1, 12)에 흑체 방사를 근사한다.

```glsl
float h = clamp((uHeat - 0.24) / 0.76, 0.0, 1.0);
emis += mix(vec3(1.0,0.035,0.004), vec3(1.0,0.095,0.020), h)
        * pow(h,1.6) * 2.5 * (0.68 + 0.32*height) * flicker;
```

> **방출 강도를 올리면 색이 사라진다.** 강도 6.5에서는 톤매핑 곡선에서 세 채널이
> 모두 1로 몰려 흰색이 된다. 적색만 포화시키고 녹·청은 곡선의 선형 구간에 남겨야
> 최대에서도 적열로 유지된다. 강도 2.5에서 95발 시 RGB (0.94, 0.36, 0.05).
> 블룸도 채널별로 임계값을 넘기므로 붉은빛만 번진다.

하이트맵 값으로 밝기를 흔들어 균일한 발광 덩어리로 보이지 않게 한다.

## 5. 무기 시스템

무기별 파라미터 테이블 + "움직이는 부품" 그룹에 걸리는 변환으로 일반화했다.

### 메시 슬롯 (무기당 5개)

| 슬롯 | 변환 | 비고 |
|---|---|---|
| `stat` | 총기 행렬 | 고정부 |
| `spin` | `kind` 별 변환 | 움직이는 주요 부품 |
| `hands` | 총기 행렬 | 고정된 손 |
| `hmov` | `spin` 과 동일 | 움직이는 부품을 잡은 손 |
| `magm` | 탄창 낙하 변환 | 분리되는 탄창 |

### kind 별 움직이는 부품 변환

```js
kind 0 (로터리)  mMul(gunM, mRZ(spin))
kind 1 (브레이크) mMul(gunM, T(hinge) * mRX(-brk*0.78) * T(-hinge))   hinge=(0,-0.045,-0.015)
kind 2 (슬라이드) mMul(gunM, mT(0,0,slideZ))
```

## 6. 애니메이션

### 반동

```
피치 상승   pitch += kick + rand*kickR          (실제 조준점이 올라간다)
회복        상승분의 65%만 초당 0.95 rad 로 복귀 → 35%는 누적
시각 반동   recoil = vrec, 초당 vdec 로 감쇠
            이동 z += recoil*vpush,  피치 += recoil*0.055,  y += recoil*0.012
```

> **총구가 위로 들려야 한다.** 총기 전방이 −Z 이므로 `mRX(a)` 에서 a가 **양수**일 때
> 총구가 올라간다. 부호를 반대로 두면 반동에 총구가 내려간다.

> **후퇴량보다 복귀 감쇠가 무게감을 좌우한다.** 샷건은 24.8cm 후퇴에 복귀 0.80초,
> 캐논은 3.4cm에 0.11초. 아무리 많이 밀려도 빨리 돌아오면 가볍게 느껴진다.

### 브레이크 액션 재장전 (샷건, 1.30초)

단일 smoothstep 대신 구간별로 가속을 다르게 줘야 리듬이 생긴다.

```js
function brkCurve(u){
  if(u<0.16){ t=u/0.16;       return 1.06*(1-pow(1-t,3)); }   // 급개방·감속도착·오버슛
  if(u<0.26){ t=(u-0.16)/0.10; return 1.06-0.06*smoothstep; } // 되튐 정착
  if(u<0.52) return 1.0;                                       // 유지
  if(u<0.68){ t=(u-0.52)/0.16; return 1.0-t*t*t; }             // 가속 폐쇄
  if(u<0.82){ t=(u-0.68)/0.14; return 0.11*sin(t*PI)*(1-t); }  // 충돌 되튐
  return 0;
}
```

각속도가 열릴 때 589°/s → 98°/s(감속 도착), 닫힐 때 56°/s → 455°/s(가속 충돌)로 바뀐다.

이벤트: 0.12 탄피 배출 + 충격 0.60 / 0.42 장전 / 0.68 폐쇄 슬램 + 충격 1.00.

> **마지막 탄 발사 직후 바로 열면 반동 동작과 겹쳐 오작동처럼 보인다.**
> `reldly` 만큼(샷건 0.55초) 뜸을 들인다.

### 슬라이드 왕복 (권총)

발사 사이클(0.16초) 중 앞 35%에 46mm 후퇴, 나머지 65%에 전진.
후퇴가 전진보다 빨라야 튕기는 느낌이 난다. 탄이 비면 후퇴한 채 고정,
재장전 88% 지점에서 전진하며 충격.

재장전 1.35초 타임라인: 0.24 탄창 분리(충격 0.38) → 0.30 완전 이탈 →
0.76 상승 시작 → 1.03 삽입(충격 0.70) → 1.19 슬라이드 전진(충격 0.85).

### 충격(jolt)

변수 하나(초당 13 감쇠)가 뷰모델의 상하 위치와 피치에 동시에 걸린다.
이벤트마다 0.38~1.00을 주입한다.

### 아이들 흔들림 (전 무기 공통)

정지 시 뷰모델의 이동 3축·회전 3축에 걸리는 미세 흔들림.
이동 최대 7.6mm, 회전 최대 0.86도.

```
주파수  0.63 0.77 0.85 0.91 1.09 1.27 1.73 2.33 2.61   (공통 주기 없음)
```

> 주파수를 하나만 쓰면 왕복이 눈에 보여 기계적으로 느껴진다.
> 서로 나누어떨어지지 않는 값을 겹쳐야 같은 자세가 반복되지 않는다.

이동·사격·재장전 중에는 0.25초 만에 사라지고 멈추면 0.8초에 걸쳐 살아난다.
사라지는 쪽을 세 배 빠르게 잡은 것은 사격 순간 흔들림이 반동과 섞이면 지저분해지기 때문이다.

## 7. 이펙트

### 파티클

인스턴싱 쿼드 하나로 전부 처리한다. 스프라이트 텍스처 없음.
인스턴스당 13 float: `pos3 / size,stretch,intensity,kind / col3 / dir3`.

- `stretch > 0` 이면 `dir` 방향으로 늘린 빌보드(예광탄), 아니면 카메라 정면 빌보드
- `dir.x` 는 stretch가 0일 때 스프라이트 롤 각도로 재사용
- 프래그먼트에서 `kind` 로 형태 분기
  - 0 부드러운 플룸 `pow(1-r, 1.7)`
  - 1 단단한 스파크·예광 `pow(1-r, 3.4)`
  - 2 총구 화염 — `cos(각도*2.5)` 로 5갈래 별 + 밝은 코어
  - 3 연기 — 완만한 로브로 원형 회피

출력은 프리멀티플라이드 `vec4(col*I*a, a*I)`. 가산과 알파 양쪽에서 성립한다.

**세 패스로 나눈다.**

| 패스 | 블렌드 | 뎁스 | 내용 |
|---|---|---|---|
| 1 | `ONE, ONE_MINUS_SRC_ALPHA` | 테스트 | 연기 |
| 2 | `ONE, ONE` | 테스트 | 예광탄·스파크·착탄 |
| 3 | `ONE, ONE` | 없음 | 총구 화염 (총기 위에 항상) |

> **연기는 가산으로 그리면 밝은 배경에서 아예 보이지 않는다.** 배경을 어둡게
> 만들 수 없기 때문이다. 알파 패스를 따로 둬야 한다.

### 탄피

중력 12, 바닥 반발계수 0.34, 오일러 각 적분 텀블링. 최대 34개, 수명 4.2초.

> **배출 속도는 화면 좌표계에서 최적화해야 한다.** 배출구가 화면 우하단
> 모서리(NDC 0.99)에 있으면 옆으로 던지는 즉시 프레임 밖이고, 카메라 쪽(+z)으로
> 던지면 0.13초 만에 카메라 뒤로 빠진다. 궤적을 시간별로 투영해서 화면 우측
> (NDC x 0.25~0.95) 체류 시간이 가장 긴 조합을 탐색했다 → 캐논 `[0.75, 3.9, -2.6]`, 약 0.9초 체류.

## 11. 화면 배치를 계산으로 잡기

탄약 게이지 위치를 눈으로 맞추려다 세 번 실패했다. 화면 좌표로 역산해야 한다.

```
NDC → 뷰 공간:  x/(-z) = ndc.x / proj[0],   y/(-z) = ndc.y / proj[5]
총기 로컬     = 뷰 좌표 − 뷰모델 오프셋(vm)
시선각        = acos(dot(패널 법선, 정규화한 카메라 방향))
```

실제로 발견한 문제들:

- 캐논 게이지를 측면에 붙였더니 시선각 67도. 캔트를 줘서 0.7도로 교정.
- 샷건 게이지가 NDC y −1.41 로 화면 밖. 리시버 뒤쪽은 카메라에서 21cm라
  그 깊이의 세로 시야가 ±14cm뿐이었다.
- 그다음엔 안전띠(116×106mm)가 그 자리 몸통 단면(111×96mm)보다 굵어서
  게이지가 띠 부피 안에 파묻혔다. 메시 정점을 직접 훑어 검증했다.
- 권총도 초기 배치에서 게이지·방아쇠울·탄창이 전부 화면 밖이었다.
  작은 총은 뷰모델 오프셋을 큰 총과 같이 쓰면 뒤쪽이 통째로 잘린다.

**검수 방법**: 특정 머티리얼 ID의 정점만 뽑아 XZ 발자국을 구하고,
그 위로 올라오는 다른 파츠의 정점 수를 세면 가림 여부를 정확히 알 수 있다.

## 12. 네이티브 이식 노트

GLSL은 그대로 간다. JS의 메시 생성부는 C로 약 300줄.

용량 추정치(측정값 아님):

| 항목 | 추정 |
|---|---|
| 지오메트리 생성기 | 30~40 KB |
| 셰이더 소스 (미니파이 후) | 15~25 KB |
| 무기·레벨 파라미터 블롭 | 5 KB 내외 |
| 텍스처 | 0 (GPU에서 생성) |

1.44MB를 위협하는 것은 3D가 아니라 **CRT/표준 라이브러리와 오디오**다.

### 아직 없는 것

1. **소리.** 총기 감각의 절반 이상이 소리에서 온다. WebAudio/네이티브 신스로
   절차적 합성(노이즈 버스트 + 저역 임펄스 + 회전 톤)이 필요하고,
   1.44MB 제약에서는 어차피 이 방법뿐이다. 가장 큰 구멍.
2. **조준점과 명중 피드백.** 예광탄이 바닥에만 닿는다. 표적과 히트마커가 없으면
   사격 루프 자체를 평가할 근거가 없다.
3. **탄흔 데칼.** 착탄 스파크는 있으나 흔적이 남지 않아 결과가 축적되지 않는다.
4. **탄피 인스턴싱.** 현재 개당 드로우콜(최대 34회). 적이 늘면 파티클처럼 옮겨야 한다.

### 코드 구조 권고

무기가 늘 때마다 같이 늘려야 하는 배열이 `WEAPONS`, `wstore`, `WEP`, `mPick`
네 개다. 하나를 빠뜨려 런타임 오류가 났다. 무기 구조체 하나로 묶는 편이 안전하다.

프레임 지역 변수와 짧은 전역 변수명(`W`=캔버스 너비, `pz`=플레이어 Z)이 세 번 충돌했다.
프레임 상태를 구조체에 담아 `st.playerZ`, `st.pumpOfs` 처럼 접근하면 이 부류가 사라진다.

## 13. 라이선스 관련

레퍼런스로 참고한 이미지(DOOM 콘셉트 아트, 언리얼 토너먼트 Enforcer)는
저작권이 있는 게임 에셋이다. 형태를 복제하지 않고 같은 계열의 오리지널
디자인으로 만들었다. 상용 배포 시에도 이 원칙을 유지할 것.
