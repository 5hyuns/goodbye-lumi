**Winner, 1.44 MB Game Dev Contest 2026.**

A first-person sci-fi horror shooter that fits on a floppy disk. The whole
game is one Windows executable of about 1 MB. It has no DLLs of its own and
not one asset file. Every texture, mesh, weapon, sound and light is
generated in code when the game starts.

> You are the last one left aboard. The only light still working is a
> maintenance drone, and she is not coming with you.

You wake in the crew quarters of a dying starship, 340 days after everyone
else evacuated. LUMI, the ship's maintenance drone, has been waiting all that
time for someone to answer. Five of the six escape bays are already empty.
Fight through the dark, recover three energy packs and power up the last
capsule before the ship, or LUMI, runs out.

## How it was made

GOODBYE LUMI was made by a 3D designer who cannot read or write code. The
whole game was built by giving AI instructions in plain words, and the code
was never opened along the way. From the first plan to the contest entry
took about a week. The [making-of](https://5hyuns.github.io/goodbye-lumi/)
shows how LUMI, the ship, its textures and its props came together, with
figures you can play with, in English,
[한국어](https://5hyuns.github.io/goodbye-lumi/ko.html),
[日本語](https://5hyuns.github.io/goodbye-lumi/ja.html) and
[Русский](https://5hyuns.github.io/goodbye-lumi/ru.html).

## Features

- **Nothing on disk but code.** There are no textures, models, sounds or
  level files. A procedural material compiler, a mesh kit and a radiosity
  light bake build the ship at startup in a few seconds.
- **A ship that gets worse.** Three sinking stages change the lighting, the
  geometry and the routes.
- **A companion who is the light.** LUMI navigates, opens locked doors,
  reads out your vitals and carries the widest lamp on the ship.
- **Three procedural weapons:** sidearm, double-barrelled shotgun and rotary
  cannon. Each one is modelled, animated and heard in code.
- **Korean, English and Japanese**, switchable on the title screen.

## Controls

WASD move · mouse look · LMB fire · R reload · F light · E interact ·
1 / 2 / 3 weapons · Shift run · C or Ctrl crouch · Space jump · Esc quit

## Building

The game is C99 against Win32 and OpenGL 3.3 core, with no libraries.

1. Download [w64devkit](https://github.com/skeeto/w64devkit) and unpack it
   to `C:\w64devkit`. `native/build.sh` adds `C:\w64devkit\bin` to `PATH`
   itself, so you do not need to install it.
2. Install Python 3. It is used only to draw the icon (`tools/mkicon.py`,
   standard library only).
3. From a w64devkit shell (or Git Bash):

   ```sh
   sh native/build.sh          # release build -> native/build/playlumi.exe
   sh native/build.sh debug    # -O0 -g, console attached
   ```

   The build prints the exe's size against the contest's 1,474,560-byte cap.

`native/src/vmw.c` is compiled without `-ffast-math` on purpose.
`build.sh` explains why.

## What is in this repository

```
native/src/         the game: renderer, radiosity bake, materials, audio,
                    AI, story, HUD and fonts (C99, Win32, OpenGL 3.3)
native/build.sh     two gcc calls and a windres
tools/              the generators that write native/src's data files, and
                    the checks that compare the exe against them
src/derelict/       the browser previz the ship was designed and lit in
                    (map.html, kit.html; generated by tools/)
src/sector-c/       the browser engine the previz is built on
props/              LUMI's frozen geometry generator and the room-prop bench
story/              dialogue, scenes and encounters as data
ref/                the deck plan the whole ship is built from
docs/               file map, engineering notes, original design documents
archive/            documents from the contest period, kept as a record
making/             the HTML prototypes, concept sheets and design notes each
                    piece started from
```

- [`docs/FILEMAP.md`](docs/FILEMAP.md) lists every file and what it does.
- [`docs/engineering-notes.md`](docs/engineering-notes.md) records 75
  problems hit along the way, each with its cause and fix.
- [`CLAUDE.md`](CLAUDE.md) is the working manual the game was developed
  with: which file owns which change, and the house rules.

The level, story, props and fonts are already compiled into five generated
files in `native/src/`, so the game builds from `native/` alone. Rebuilding
them needs Python 3 and Node (standard library only, nothing to install):

```sh
# the ship: deck plan -> previz pages -> the exe's level data
python tools/build_ship.py && python tools/splice.py && python tools/weapons.py \
  && python tools/doors.py && python tools/decals.py && python tools/deckmap.py
python tools/kitview.py       # the part bench, src/derelict/kit.html
python tools/nativepack.py    # -> native/src/plan_data.h
python tools/storypack.py     # story/*.json -> native/src/story_data.h
python tools/propglsl.py      # prop surfaces -> native/src/props_glsl.h
node tools/propexport.js      # prop shapes -> native/src/props_gen.c
python tools/jafont.py        # Japanese glyphs -> native/src/jafont_data.h (Windows)
```

The previz pages open directly in Chrome; `?fast` shortens the light bake.
