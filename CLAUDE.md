# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

GOODBYE LUMI, a first-person SF horror shooter in one Windows executable:
procedural materials, a radiosity bake at load, no assets on disk. Short map:
`docs/reports/PROJECT_INDEX.md`; every file: `docs/FILEMAP.md`; line of every
section and export: `docs/symbols.json`.

## Quick reference

```bash
sh native/build.sh                         # release exe, prints its size vs the cap
sh native/build.sh debug                   # -O0 -g
native/build/playlumi.exe -shot out.png -cam x,y,z,yaw,pitch   # photograph a view
native/build/playlumi.exe -auto 400 -log   # plays itself; transcript in ./derelict.log
python tools/storypack.py                  # after editing story/*.json, then rebuild
```

There is no test suite. Correctness is checked by comparing an exe
instrument against a tool that runs the original JS (section 9). A change to
how something looks is proved with `-shot`, not by reading the code.

## 1. What this is, and what the HTML is

The game won the **1.44 MB Game Dev Contest 2026**. The rule it was built
under still holds for every change: the executable plus its runtime must fit
**1,474,560 bytes** uncompressed. `native/build.sh` prints the remaining
budget after every build. Original design: `docs/design/gdd.md`.

The contest banned browser games, so `src/derelict/map.html` is the
**previz** (the place the ship was designed and lit) and `native/` is
**the game**: Win32 + OpenGL 3.3, no libraries, no DLLs of its own, no
assets. It imports only GDI32, KERNEL32, msvcrt, OPENGL32, USER32 and WINMM,
all of which ship with Windows. Content is not the constraint: the whole
ship uses about three quarters of the cap, and the bake that took the
browser 95 s takes the exe about 5 s.

## 2. Problems already solved

`docs/engineering-notes.md` records every trap hit so far, each with its
cause and fix. Many of them look correct in the code and fail only on screen
or in a long run (argument evaluation order in C, `-ffast-math` breaking a
cancellation test, a ray result held in globals, pools that fall back to
slot 0). Read the entries for a subsystem before changing it.

## 3. The native build

```
native/build.sh              two gcc calls and a windres; `debug` for -O0 -g
native/src/*.c               hand-authored, the port
native/src/plan_data.h       GENERATED by tools/nativepack.py
native/src/story_data.h      GENERATED by tools/storypack.py
native/src/props_gen.c       GENERATED by tools/propexport.js
native/src/props_glsl.h      GENERATED by tools/propglsl.py
native/src/jafont_data.h     GENERATED by tools/jafont.py -- the only
                             typeface in the tree that is stored
native/src/torch.h           the flashlight beam, as GLSL the three
                             scene shaders concatenate -- not generated
native/build/icon.ico        GENERATED by tools/mkicon.py -- LUMI, drawn
                             at six sizes, wrapped by windres
native/build/playlumi.exe    the submission
```

Three of those files are not ports of anything in the previz, because the
previz has no equivalent: `menu.c` (the title card, the eyelid wake and the
one flag every string answers to), `props.c` (the room props of
`props/props_v01/`, as assemblies of the thirteen instanced solids at the
bench's own dimensions -- the bench's atlas machine is a second texture
pipeline and this build cannot afford one), and `lumimesh.c` -- which IS a
port, but of `props/lumi_v02/lumi_geometry.js` rather than of anything in
map.html.  LUMI is frozen: `props/lumi_v02/LUMI-SPEC.md` §0 says not to
rebuild her out of primitives, and `lumimesh.c` is that generator carried
across statement for statement.  Its 35 parts are grouped by material into
thirteen instanced ranges.  A new `.c` goes in `build.sh`'s
`SRC` list; there is no makefile because there is still nothing to decide.

Two calls, not one, because `vmw.c` is compiled **without `-ffast-math`**:
its `finalize()` decides a welded corner has no tangent of its own by whether
a sum of face tangents cancels, and reassociating that sum breaks the test.
`build.sh` carries the measurement. Nothing else in the ship asks a float
whether it cancelled.

The compiler is **w64devkit at `C:\w64devkit`** — downloaded, not installed,
and not on PATH. `build.sh` adds it itself; anything else that shells out to
gcc must too, or it fails with `cannot execute 'as'`.

**The plan is data; everything else is code.** `tools/nativepack.py` hands
map.html's own LEVEL and MATERIAL COMPILER sections to node with a dumper
appended, and writes `plan_data.h` (its header comment and the `level` line
of `-log` give the counts). A regex
parser would be a second thing to keep in step with the first. Re-run it after
any change to the Python chain. The bake, the operator library, the mesh
machine, the 21 kit parts, the shaders, the entity pass, the audio graph and
the three procedural weapons are ports, not transcriptions.

The exe carries its own instruments, so a claim still comes with evidence:

```

playlumi.exe -shot g.png -gun 2 -fire              # a named gun, mid-shot

playlumi.exe -probe 145,420,210,650,199,455        # ... and what can reach what
playlumi.exe -spider 3                             # three of them, in front of you
playlumi.exe -font                                 # the Hangul machine, on a card

playlumi.exe -fast -debug N -log -dev              # coarse bake, a channel, a
                                                   # transcript, the developer HUD
playlumi.exe -title            # the title card, photographed
playlumi.exe -title -options   # ... and the language page
playlumi.exe -wake 14          # the eyelids, 1.4 s into the wake, held
playlumi.exe -en               # start in English  }  the card's other two
playlumi.exe -ja               # start in Japanese }  settings
playlumi.exe -debug 10         # what Gouraud lost in the lightmap and the
                               # frame put back -- the lattice, lit up
playlumi.exe -debug 11         # the same frame WITHOUT that correction, so
                               # before and after are one build apart
```

Also `-flash` (the Schlick-clamp case), `-god` and `-mortal` (`-auto` is
immune unless told otherwise). There is **no `-console`**; `-dev` is the HUD.
Every one of these flags skips the title card, or the instrument would sit
on it waiting for a keypress that is never coming.

`-probe` now prints `P` for a cell with a prop standing on it, which is how
"the furniture is not in the way" gets checked rather than asserted.

The C material compiler agrees with the JS one to four decimals on every
channel; that check also pins ihash, the periodic noise and the cellular
basis, because every one of those numbers is a function of them. The C mesh
builder agrees with the JS one the same way, per vertex channel and per
mesh, which pins loft, lathe, chamferBox, the 50-degree smoothing and
mulberry32 — `-vmw` against `node tools/vmwcheck.js`.

## 5. Build chain

```
ref/ship_deck_plan_v6_fixed.svg
  deckplan.py     transcribe the plan            (imported, not run)
  build_ship.py   plan -> brushes                -> tools/_shell.js, _lights.js
  splice.py       graft onto the sector-c engine -> derelict.html
  weapons.py      splice tools/weapons.js        -> derelict.html (in place)
  doors.py        splice tools/doors.js          -> derelict.html (in place)
  decals.py       splice tools/decals.js         -> derelict.html (in place)
  deckmap.py      lay the kit over the plan      -> map.html
```

Run in that order, all of it, after touching anything upstream:

```bash
python tools/build_ship.py && python tools/splice.py && \
python tools/weapons.py && python tools/doors.py && python tools/decals.py && \
python tools/deckmap.py
```

`kitview.py` is a separate branch off `derelict.html` -> `kit.html`.
Order matters: `decals.py` needs `doors.py` first (a bound mark asks
`adBindAt()` which leaf it hit).

Five one-step chains write into `native/src/` and do not touch the previz.
These are the **only** five generated files in the C tree:

```bash
python tools/storypack.py       # story/*.json  ->  native/src/story_data.h
python tools/nativepack.py      # map.html      ->  native/src/plan_data.h
python tools/propglsl.py        # propview.html ->  native/src/props_glsl.h
node tools/propexport.js        # propkit.js    ->  native/src/props_gen.c
python tools/jafont.py          # every ja string ->  native/src/jafont_data.h
sh native/build.sh              # ... and then the exe, which prints its size
```

`nativepack.py` after any change to the Python chain above; `storypack.py`
after any change to `story/*.json` or to the tables inside the packer;
`propglsl.py` after any change to `propview.html`'s `LIB_GLSL`, which is
the bench's eleven height functions and is what surfaces every prop.
`propexport.js` after any change to `propkit.js`, which is every prop's shape.
`jafont.py` after any change to Japanese text anywhere -- it rasterises the
glyphs the story USES and no others, so a new kanji with no run of the tool
behind it draws as a hollow box.

And the symbol map, after moving code:

```bash
python tools/mkindex.py         # -> docs/symbols.json
```

## 7. Reading the big files: by range, never whole

`map.html` is over 800 KB (about 210K tokens), `derelict.html` and
`kit.html` are close behind, and `story.c` is the largest C file. Reading any
of them whole is never correct. The built pages share fourteen numbered
sections: MATH, MATERIAL IDS, LEVEL, LIGHTS, MATERIAL COMPILER, RADIOSITY
BAKE, GEOMETRY, GL, PLAYER, INPUT, PROCEDURAL AUDIO, HUD, BUILD, FRAME. Their
current line numbers are in `docs/symbols.json` (`pages`), and
`python tools/mkindex.py` rewrites it after code moves:

```bash
python -c "import json;[print(s['line'],s['name']) for s in json.load(open('docs/symbols.json',encoding='utf-8'))['pages']['src/derelict/map.html']['sections']]"
sed -n '<from>,<to>p' src/derelict/map.html
```

Locate first with a narrow grep, then read the range around the hit —
a broad grep over this file returns ~45 KB of output on its own.

## 9. Verifying a change

Judge the exe first: `-shot` for a picture, `-auto N -log` for a run. The
instruments that print numbers write `derelict.log` in the current directory
when given `-log`, and the game keeps running afterwards, so close it. A
port check compares that log with a node tool that runs the original JS:

```bash
node tools/vmwcheck.js > a.txt
native/build/playlumi.exe -vmw -log      # then close the window
grep '^vmw ' derelict.log > b.txt
diff a.txt b.txt   # vertex counts must match exactly; float sums agree
                   # to within the last printed decimal; the exe adds a total row
```

`-lumimesh` against `tools/lumicheck.js` and `-mats` against
`tools/matview.js` work the same way. For the previz, open
`src/derelict/map.html` in Chrome; `?fast` cuts the bake (the full one is
about 95 s).

- `node tools/shot.js` drives a real Chrome and photographs the page.
- `node tools/matview.js` compiles one material to PNG headlessly, no bake.
- `node tools/kitcost.js` sizes a MODULES list in faces before building it.
- `node tools/vmwcheck.js` runs map.html's own VMW section against a stub
  WebGL context and prints every viewmodel mesh as six numbers, to diff
  against `playlumi.exe -vmw`. The only check in the tree that can catch a
  mesh that is wrong but still looks plausible.
- `playlumi.exe -wav mix.wav` renders the audio bench with no device and
  drops `mix.wav.events.txt` beside it naming what fired when;
  `python tools/wavan.py mix.wav mix.wav.events.txt` reads the pair and prints
  a line per sound. The two columns that matter are `flat` -- spectral
  flatness, 0.0003 for a bare square wave and 0.3 for a piece of steel being
  struck -- and `S/N`, how far the sound stands over the ambient bed. It is
  the only check in the tree that can tell a sound that is CORRECT from one
  that is a musical note, and the only one that can hear that a sound is
  quieter than the ship it plays over.
- `playlumi.exe -font` puts all three alphabets on one card: the Hangul
  the strokes build, and the Japanese sheet under it. A hollow box there
  means `tools/jafont.py` has not been re-run.
- `node tools/lumicheck.js` does the same for LUMI, against
  `playlumi.exe -lumimesh`: all 35 parts, counts and bounding box. The
  spec's own checksum is three totals, and three totals cannot tell a
  correct mesh from one built with a transposed rotation.

Claims about how something *looks* need a screenshot, not a reading of the code.

## 10. House rules for this project

- `git diff` before re-reading a file. The tree is committed; use it.
- No primitive may read as itself — a box that reads as a box is rejected.
- No right angle is left open; the corridor section is an octagon.
- Geometry owns 80 mm and up, the texture owns everything below.
- Accents are ochre, amber and cyan only. Nothing else is coloured.
- Anything lit must also be a lamp, or the bake ignores it (`emit`).
- Parts get numbers and are reviewed one at a time on the kit bench.

## 11. Conventions

**Everything is generated in code.** No PNG, no OBJ, no WAV in the tree — a
texture is a recipe in `shipmaterials.py`, a mesh is a `make()` in `kit.js`, a
sound is built from the engine's noise buffer. Bytes on disk are bytes off the
budget, so this is a constraint, not a taste.

**The story is data, the same way the plan is.** `story/` holds the design
(dialogue, encounters, the item and door tables) and
`tools/storypack.py` compiles it (and prints the counts) to `native/src/story_data.h`. Re-run it
after any change to `story/*.json` or to the tables inside the packer.
What stays as code is what is genuinely logic: the opening's order, what a
checkpoint restores, and how a wave knows it is finished.

**No dependencies.** Python is stdlib plus sibling modules; node is
`child_process fs os path zlib` and nothing else. There is no package.json and
no install step. Reach for a stdlib call before a package.

**Splices are anchored and idempotent.** `sub(old, new, label)` and
`cut(a, b, new, label)` assert their anchor exists and carry a label so a break
names itself. Anchor on text that occurs only in the source, so re-running the
chain is always safe.

**`_` prefix in `tools/` means generated.** `_shell.js`, `_lights.js`,
`_map_modules.js` are written by the tools. Never hand-edit one.

**Comments say why, and carry the measurement.** The house style states the
insight in caps and then explains it — `TWO SEPARATE PROBLEMS, TWO SEPARATE
FIXES`, `A CAP THAT FADES RATHER THAN POPS` — and module docstrings record what
the thing actually cost: `377 full cells / 2,176 shell, 965 k triangles, 257
lamps -> 2.7 s compile + 95 s AO`. A number in a docstring is a measurement, so
re-measure before changing it rather than adjusting it to taste.

**Numbers are named at the top.** Module-level `SHOUTING_CONSTANTS` hold every
tunable — `BUDGET`, `TEX_SCALE`, `AD_OPEN_S`, `RIB_PITCH`. A literal buried in a
function is a bug waiting to be un-findable.

**Language is mixed and inconsistent.** Code and comments are English; `kit.js`
part subtitles are English, `propkit.js` prop subtitles are Korean. No rule has
been set — match the file you are in.
